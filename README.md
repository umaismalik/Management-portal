# Solexes Ticket Management Portal

## Meeting notes and voice transcription

The Meetings and Meeting Notes areas are scoped to the selected project. Meetings can be in person or online using Jitsi, Google Meet, Microsoft Teams, or Zoom. Jitsi uses its official external meeting API to embed camera and microphone access in the dashboard. External-provider buttons open that service directly; the app does not have Google/Zoom OAuth integration, so it cannot create a shared external room automatically. Create the room at the provider and paste its invite URL if you want invitations from this app to include the link. Without that URL, invitations explicitly tell invitees to request the link from the organizer. A free personal Google account can host group meetings up to 60 minutes; provider account limits and recording policies still apply. Anyone with a public Jitsi room link may join, and public Jitsi duration/availability is not guaranteed. Recording requests microphone permission only and records the selected device microphone without browser noise/echo processing; it cannot capture remote-call audio directly unless the microphone can hear the speakers. Each saved recording becomes its own monthly project note with transcript, generic key points, member-specific notes, and editable action items with assignees, deadlines, status, and comments. Transcription runs in approximately one-minute chunks to keep memory use and progress intervals bounded, but a full hour can still take substantial time on CPU-only devices. Audio/transcript capture and transcription require explicit user interaction; saved recordings are uploaded to the app's configured storage. The API limits audio upload to 4 MB when using remote Supabase storage and 25 MB with local file storage; if the upload fails, the note and transcript remain saved and the clip can be retried. Local filesystem storage is not durable on ephemeral hosting such as Vercel, so configure persistent storage before relying on deployment for data retention.

Voice transcription uses the multilingual Whisper Base model with q4 quantization on WebGPU when available and WASM/CPU otherwise, prioritizing faster local inference over larger model accuracy. Audio is translated into English and split into 15-second chunks; the status reports the active chunk and elapsed time while inference runs. The smaller model must be downloaded the first time after this update. The app uses the active project team roster and common pronunciation/spelling aliases for Sami, Irfan, Zunaira, Mashal, Haider Ali, Umais, Adil, and Mashhood to suggest individual summary cards when a member's name and a clear turn-taking phrase such as "your turn" or "you are next" are recognized. Matching tolerates a one-character spelling difference and common Soundex-like name variants; when a match is ambiguous, it avoids guessing. This is a text heuristic, not voice identification, speaker diarization, model training, or a guarantee of correct attribution. Review and correct notes before saving or emailing. Each recorded clip can be saved as an independent monthly note. Saving meeting notes sends non-empty member-specific summaries to the matched team members by email. Newly assigned action items also email their assignee. The meeting controls let users select automatic language detection, English, or Urdu as the spoken-language hint; choosing the known language can help with short clips. No Cloudflare account, API token, or paid transcription service is required. The open-source inference runtime is loaded from jsDelivr and model files download from Hugging Face on first use; both require an internet connection. The browser caches model files for later use. Transcription runs in the browser; when the user explicitly saves a clip as a note, its audio and resulting transcript/notes are uploaded to the app's configured storage. No automatic speech recognition model can guarantee 100% accuracy.

Voice recording supports pause/resume and multiple clips in one meeting note. Finishing a clip translates the speech and updates its invitee summary cards; select **Record another clip** to continue. Transcription requests are serialized and duplicate development-mode requests for the same clip share one transcription job. The latest clip can be played back to confirm the microphone captured it clearly; a failed transcription can be retried without recording again.

Data storage: when a real `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` are set, the portal stores its database and uploaded files in Supabase (free tier), which is what makes Vercel hosting possible. If the URL is still `your-project.supabase.co`, the app uses local file storage in `data/db.json` and `data/uploads`; no Supabase setup is needed for local development. To enable Supabase later, use the actual project URL from Supabase **Project Settings → API**, then run `supabase.sql` once and `node --env-file=.env.local scripts/migrate-to-supabase.js` to move existing local data.

## Email delivery

All application emails (project invitations, password resets, meeting invitations and participant summaries, ticket notifications, and deadline reminders) use Resend when `RESEND_KEY` and a verified-domain `RESEND_FROMEMAIL` are configured on the server. For a simple domain-free setup, configure Gmail SMTP: when `SMTP_HOST=smtp.gmail.com`, the app uses Gmail directly and does not require Resend domain verification. Use a Google App Password (not the normal account password; enable 2-Step Verification first), `SMTP_PORT=465` or `587`, `SMTP_USER` (the full Gmail address), `SMTP_PASS` (the 16-character App Password; spaces are removed automatically), and `SMTP_FROM` (a sender matching that Gmail account). A Gmail authentication error means the App Password or account settings need correction. With other SMTP hosts, a failed Resend send falls back to SMTP and reports both provider errors if delivery still fails. Keep provider credentials in server environment variables only; never expose them to client-side code or commit them. Restart the app after changing environment variables. Email APIs report provider errors for invitation and meeting sends; deadline reminder failures are logged and are not marked as sent so they can be retried.
